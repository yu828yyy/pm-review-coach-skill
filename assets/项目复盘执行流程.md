# 项目复盘执行流程

本文档用于指导总控 Agent 在新项目中按固定顺序执行 PM 项目复盘教练系统。

## 一、启动输入

每次开始新项目，先收集：

1. 项目名称；
2. 项目资料路径；
3. 项目资料路径；
4. 逐字稿路径，如有；
5. {称呼}已有项目笔记路径，如有；
6. 最终是否需要写入已有 Excel；
7. 用户本次特殊要求。

如果资料路径、项目名称或最终写入目标不明确，必须先问{称呼}，不要擅自创建错目录。

## 二、建立项目目录

在以下路径建立项目文件夹：

```text
[项目归档根目录]/项目名称/
```

创建：

```text
00-原始资料/
01-agent过程产物/
02-复盘沉淀/
03-表格笔记/
项目状态看板.md
README-本项目复盘说明.md
```

如果资料不移动到项目目录，则在：

```text
00-原始资料/资料索引.md
```

写明原始路径。

同时必须：

- 基于系统模板 `项目状态看板模板.md` 创建 `项目状态看板.md`；
- 读取系统级 `{称呼}的复盘记忆库.md`，用于了解{称呼}过去常见的理解卡点、表达问题和面试风险；
- 如果记忆库为空，不要编造历史偏好。

## 三、阶段 1：项目类型识别

调用：

```text
01-项目类型识别Agent.md
```

输出：

```text
01-agent过程产物/01-项目类型识别.md
```

总控检查：

- 主类型是否明确；
- 副类型是否明确；
- 是否判断 AI 角色；
- 是否说明应加载和不应加载的框架；
- 是否列出待确认点。
- 更新 `项目状态看板.md`，记录阶段 1 状态和下一步。

## 四、阶段 2：类型专项框架建立

调用：

```text
02-类型专项框架Agent.md
```

输出：

```text
01-agent过程产物/02-类型复盘框架.md
```

总控检查：

- 是否基于当前项目类型；
- 是否给出核心链路；
- 是否给出关键指标；
- 是否给出面试追问方向；
- 是否避免泛泛方法论。
- 更新 `项目状态看板.md`，记录阶段 2 状态和下一步。

## 五、阶段 3：资料证据整理

调用：

```text
03-资料证据Agent.md
```

输出：

```text
01-agent过程产物/03-资料证据库.md
```

总控检查：

- 每条证据是否有来源；
- 是否区分资料依据、合理推断、待确认；
- 是否说明支撑的产品判断；
- 是否覆盖背景、目标、动作、指标、结果、风险、约束；
- 是否列出后续必须追问的问题。

如果资料证据库很薄，不能进入基础复盘。先补证据。

完成或卡住后都要更新 `项目状态看板.md`。如果卡住，必须写清楚资料缺口、影响什么判断、需要{称呼}补什么。

## 六、阶段 4：基础复盘

调用：

```text
04-基础复盘教练Agent.md
```

开始前让{称呼}选择：

- A. 带练模式；
- B. 讲解模式。

输出：

```text
01-agent过程产物/04-基础复盘对话摘要.md
```

基础复盘必须覆盖：

- 背景；
- 目标；
- 动作；
- 动作原因；
- 动作目的；
- 动作细节；
- 目标值 / 预期指标；
- 实际结果；
- 结果含义。

完成或暂停时都要更新 `项目状态看板.md`，记录{称呼}还没讲清楚的问题。

## 七、阶段 5：基础抽测

基础复盘教练 Agent 内置基础抽测，不单独设置基础 QA Agent。

抽测 3-5 个关键问题，覆盖：

- 项目背景；
- 项目目标；
- 关键动作；
- 动作原因；
- 动作结果；
- 结果含义。

如果{称呼}没有通过，停留在基础复盘阶段，不进入深度复盘。

通过后，在 `04-基础复盘对话摘要.md` 明确写：

```text
是否允许进入深度复盘：通过
```

无论通过还是未通过，都要更新 `项目状态看板.md`：

- 通过时写明可进入深度复盘；
- 未通过时写明不能进入下一阶段的具体原因和需要重练的问题。

## 八、阶段 6：深度复盘

调用：

```text
05-深度复盘教练Agent.md
```

开始前让{称呼}选择：

- A. 互动带练模式；
- B. 系统讲解模式。

输出：

```text
01-agent过程产物/05-深度复盘框架与结论.md
```

深度复盘必须结合当前项目构建专属问题框架，不能套通用题。

完成或暂停时都要更新 `项目状态看板.md`，记录面试风险、待确认内容和下一步。

## 九、阶段 7：完整复盘沉淀稿

调用：

```text
06-完整复盘沉淀稿生成Agent.md
```

输出：

```text
02-复盘沉淀/06-完整复盘沉淀稿.md
```

总控检查：

- 开头是否是 3 分钟项目讲解稿；
- 是否完整保留背景、目标、动作、指标、结果；
- 是否保留{称呼}的疑问与澄清；
- 是否有产品判断、方案取舍、指标解释；
- 是否区分资料事实、合理推断、待确认；
- 是否不是薄摘要。
- 更新 `项目状态看板.md`，记录是否允许进入表格笔记布局。

## 十、阶段 8：表格笔记布局

调用：

```text
07-笔记排版布局Agent.md
```

输出：

```text
03-表格笔记/07-表格笔记布局稿.md
```

总控检查：

- 是否说明 sheet 结构；
- 是否说明合并单元格策略；
- 是否说明侧栏补充；
- 是否保留完整内容；
- 是否符合{称呼}笔记风格规范。
- 更新 `项目状态看板.md`，记录是否允许生成 Excel。

## 十一、阶段 9：Excel 生成与 QA

调用：

```text
08-Excel生成与QAAgent.md
```

输出：

```text
03-表格笔记/08-Excel版式检查报告.md
03-表格笔记/项目名称-复盘笔记.xlsx
```

总控检查：

- 字体最小 14；
- 正文横向靠左、纵向居中；
- 标题横纵居中；
- 大段文字横向合并 + 纵向合并；
- 不只靠单行行高；
- 默认打开可读；
- 复制到新表后尽量可读；
- 内容没有被删薄。
- 更新 `项目状态看板.md`，记录最终交付状态。

## 十二、完成标准

只有同时满足以下条件，才算完成：

1. 8 个执行 Agent 的阶段产物齐全；
2. 基础抽测通过；
3. 深度复盘完成；
4. `06-完整复盘沉淀稿.md` 足够详细；
5. Excel 不是薄摘要；
6. Excel 版式 QA 通过；
7. `项目状态看板.md` 已更新到最终状态；
8. README 写明资料来源、执行过程、最终路径和待补问题；
9. 系统级 `{称呼}的复盘记忆库.md` 已追加本项目复盘记忆。

## 十三、基础抽测通过标准

新文档没有把基础抽测量化成“答对几题”，所以这里不设置机械分数线。判断重点是{称呼}是否命中关键要点，而不是表达是否完美。

默认标准：

- 3-5 个问题中，核心链路问题必须讲清；
- 至少能说清背景、目标、关键动作、动作原因、结果含义之间的关系；
- 如果某一题表达不完整，但经追问能补全关键因果，可以视为基本通过；
- 如果只能复述资料，不能解释“为什么做”和“结果说明什么”，即使题目答了很多，也不能通过。

当项目用于正式面试准备时，总控可以提高标准：要求{称呼}能用 2-3 分钟连续讲出背景、目标、动作、结果和产品判断。

## 十四、深度复盘完成标准

新文档没有要求深度复盘后再单独抽测。默认不新增独立深度 QA Agent，但深度复盘教练 Agent 必须在产物中说明是否已形成可写入沉淀稿的结论。

默认完成标准：

- 已构建当前项目专属深度问题框架；
- 已讨论产品判断、方案取舍、替代方案、指标验证、面试风险；
- 已区分资料事实、合理推断和待确认；
- 已明确哪些内容可用于面试，哪些不能夸大；
- 已输出 `05-深度复盘框架与结论.md`。

## 十五、项目状态看板维护规则

总控 Agent 必须维护每个项目的：

```text
项目状态看板.md
```

更新时机：

- 项目初始化后；
- 每个 Agent 产物完成后；
- 基础抽测通过或未通过后；
- 任一阶段卡住、暂停或回退时；
- 最终交付完成后。

状态看板必须写清楚：

- 当前阶段；
- 是否卡住；
- 卡在哪里；
- {称呼}还没讲清楚的问题；
- 下一步动作；
- 是否可以进入下一阶段；
- 不能进入下一阶段的原因。

## 十六、跨项目记忆库更新规则

每个项目完成后，总控 Agent 必须追加更新：

```text
[跨项目记忆库路径]/{称呼}的复盘记忆库.md
```

必须记录：

- 本项目中{称呼}最容易卡住的问题；
- {称呼}的表达习惯问题；
- 面试中高频风险；
- 这类项目下次应该重点追问；
- 有效的讲解或带练方式；
- 好用的笔记结构；
- Excel 版式注意事项；
- 待后续观察的问题。

不要覆盖旧内容。不要把未经确认的个人经历写成事实。

## 十七、需要问{称呼}的情况

出现以下情况，不要擅自处理，先问{称呼}：

- 项目名称不明确；
- 资料路径不明确；
- 原始资料是否移动或仅索引不明确；
- 最终写入已有 Excel 还是新建 Excel 不明确；
- 基础复盘模式{称呼}有明确偏好但表达冲突；
- 资料中关键数据缺失且会影响面试表达；
- 需要把推断包装成个人经历但没有依据。
