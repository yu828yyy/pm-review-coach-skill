# PM 项目复盘教练系统

这是一套给{称呼}复盘产品项目使用的可复用 Agent 系统模板。

系统目标不是快速生成一份好看的 Excel，而是通过 Workflow + Agent 的方式，带{称呼}真正吃透项目，沉淀可用于面试、简历、复习和表格笔记的项目资产。

## 核心定位

- Workflow 负责固定流程，保证步骤稳定、产物完整、路径可复用。
- Agent 负责动态判断、资料依据识别、互动提问、讲解纠偏、是否进入下一阶段。
- {称呼}必须参与基础复盘和深度复盘，不能从资料直接跳到最终笔记。
- 总控 Agent 负责调度，但不能替代 8 个执行 Agent 全包。

## 固定 Agent

本系统固定使用 8 个执行 Agent：

1. 项目类型识别 Agent
2. 类型专项框架 Agent
3. 资料证据 Agent
4. 基础复盘教练 Agent
5. 深度复盘教练 Agent
6. 完整复盘沉淀稿生成 Agent
7. 笔记排版布局 Agent
8. Excel 生成与 QA Agent

另外保留一个总控 Agent，用于项目初始化、流程调度、阶段闸门检查和最终交付检查。总控不计入 8 个执行 Agent。

## 固定流程

1. 项目类型识别
2. 类型专项框架建立
3. 资料证据整理
4. 基础复盘
5. 基础抽测
6. 深度复盘
7. 完整复盘沉淀稿生成
8. 表格笔记布局
9. Excel 生成与 QA

不能一开始就生成 Excel。不能没有基础抽测就进入深度复盘。不能没有基础复盘和深度复盘就生成完整复盘沉淀稿。

## 默认项目目录

每个新项目应保存到：

```text
[项目归档根目录]/项目名称/
```

建议目录结构：

```text
项目名称/
├── 00-原始资料/
├── 01-agent过程产物/
│   ├── 01-项目类型识别.md
│   ├── 02-类型复盘框架.md
│   ├── 03-资料证据库.md
│   ├── 04-基础复盘对话摘要.md
│   └── 05-深度复盘框架与结论.md
├── 02-复盘沉淀/
│   └── 06-完整复盘沉淀稿.md
├── 03-表格笔记/
│   ├── 07-表格笔记布局稿.md
│   ├── 08-Excel版式检查报告.md
│   └── 项目名称-复盘笔记.xlsx
├── 项目状态看板.md
└── README-本项目复盘说明.md
```

如果原始资料不适合复制移动，可在 `00-原始资料/` 中保存索引说明，写清楚原始文件路径。

## 使用方式

新项目开始时，先让总控 Agent 阅读：

1. 本目录的 `README.md`
2. `项目复盘执行流程.md`
3. `项目笔记风格规范.md`
4. `项目启动信息模板.md`
5. 对应阶段的 Agent 文件
6. 当前项目的资料路径和已有笔记

然后按流程逐步执行。每个 Agent 必须留下固定产物，便于后续定位问题、补资料和复用到下一个项目。

可复用模板包括：

- `项目启动信息模板.md`
- `资料索引模板.md`
- `项目状态看板模板.md`
- `README-本项目复盘说明模板.md`

跨项目记忆文件：

- `{称呼}的复盘记忆库.md`

总控 Agent 在每个项目启动时必须创建并维护 `项目状态看板.md`，在每个阶段完成、暂停、卡住或回退时更新它。每个项目结束后，必须追加更新 `{称呼}的复盘记忆库.md`，沉淀{称呼}在本项目中暴露出的理解卡点、表达问题、面试风险和有效复盘方式。

## 质量标准

一次合格复盘不是看文件数量，而是看{称呼}是否能讲清楚：

- 项目背景是什么；
- 目标为什么这样收敛；
- 关键动作是什么；
- 每个动作为什么做；
- 动作细节、目标值和结果是什么；
- 结果说明了什么；
- 产品判断和方案取舍是什么；
- 面试官可能质疑哪里；
- 哪些是资料事实，哪些是合理推断，哪些需要继续确认。

如果这些没有达成，即使生成了 Excel，也不能认为任务完成。
