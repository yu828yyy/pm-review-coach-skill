# 项目笔记风格规范

这份规范来自高德商家智能体复盘过程，以及对 ima 播客项目笔记搭建风格的总结。

后续项目复盘时，笔记排版布局 Agent 和 Excel 生成与 QA Agent 必须引用本规范。不要每次重新设置风格研究 Agent。

## 一、核心定位

{称呼}的项目笔记不是流水账，也不是薄摘要，而是“结构化知识白板 + 面试讲述资产”。

它要帮助{称呼}做到：

1. 看得懂项目；
2. 讲得清项目；
3. 说得出为什么；
4. 能应对面试追问；
5. 后续复习时能快速回到项目逻辑。

## 二、内容风格

### 1. 先定义项目，再堆功能

不要一上来列功能点。先说明：

- 这个项目本质上在解决什么问题；
- 它处于什么业务阶段；
- 它服务什么用户 / 商家 / 平台目标；
- 它为什么值得做。

### 2. 用“为什么”串联全篇

笔记的主线应是：

```text
为什么出现这个项目
→ 为什么目标这样收敛
→ 为什么选择这些动作
→ 为什么这些动作能影响指标
→ 结果说明了什么
→ 面试中如何解释边界
```

### 3. 不是 A，而是 B

{称呼}的笔记适合用这种表达方式拉开层次：

- 不是“优化 AI 回复”，而是“把 AI 会话转成可衡量的经营转化链路”。
- 不是“做了用户分层”，而是“识别不同意图阶段，决定是否推进转化动作”。
- 不是“指标好看”，而是“指标能帮助判断假设是否成立”。

### 4. 保留从不理解到讲通的过程

不要只写最终结论。{称呼}一开始困惑、后来被讲通的地方必须保留。

这部分很重要，因为它能反映真正的吸收过程，也能暴露后续复习和面试风险。

每个疑问最好写成：

```text
我一开始不理解什么
→ 为什么会困惑
→ 资料里怎么说
→ 复盘后怎么讲通
→ 还有什么待确认
```

### 5. PM 思考必须具体

不要写空泛的“体现了产品思维”。

要写清楚：

- 这个判断从哪里来；
- 面临什么约束；
- 有哪些替代方案；
- 为什么当前方案更合适；
- 当前方案牺牲了什么；
- 指标如何验证；
- 结果能证明什么，不能证明什么。

## 三、推荐笔记结构

一个完整项目笔记应包含：

1. 3 分钟项目讲解稿；
2. 项目背景详细复盘；
3. 项目目标收敛过程；
4. 关键动作完整拆解；
5. 基础复盘中的疑问与澄清；
6. 深度复盘问题框架与讨论内容；
7. 产品判断、方案取舍与约束；
8. 指标、结果与结果解释；
9. 个人参与、项目包装与面试表达准备；
10. 待补资料 / 待确认问题。

## 四、面试资产要求

面试准备不是概念题，不要问“什么是 RAG”“什么是 CRM”这种脱离项目的问题。

面试追问必须围绕项目经历：

- 这个项目为什么要做；
- 为什么目标不是另一个；
- 为什么选这些动作；
- 这个动作你怎么判断有效；
- 如果数据不好你会怎么解释；
- 这个方案有什么风险；
- 如果重做你会优化什么；
- 你在其中体现了什么产品判断；
- 哪些说法不能夸大。

面试表达要区分：

- 资料事实；
- 项目资料中的结论；
- {称呼}经过复盘形成的理解；
- 可以包装成{称呼}个人判断的内容；
- 不能直接使用、容易夸大的内容。

## 五、防止笔记变薄

如果笔记明显比项目资料薄，通常不是排版问题，而是复盘过程不够。

常见原因：

1. 只做了摘要，没有建立证据库；
2. 只写了做什么，没有写为什么；
3. 没有保留{称呼}的疑问和纠偏过程；
4. 没有对核心判断连续追问；
5. 过早把内容压缩成面试话术；
6. 为了 Excel 好看删掉了细节。

处理方式：

- 回到资料证据库补证据；
- 回到基础复盘补背景、目标、动作、结果链路；
- 回到深度复盘补产品判断、替代方案、指标验证；
- 再生成完整复盘沉淀稿；
- 最后再做表格布局。

## 六、Excel 视觉与排版规范

### 1. 字体

- 所有内容字体最小 14；
- 不允许为了塞内容使用小字号；
- 标题可更大，但要克制，不要让表格变成海报。

### 2. 对齐

- 正文大段文字：横向靠左、纵向居中；
- 一级标题：横向和纵向都居中；
- 二级标题：横向和纵向都居中；
- 三级标题：横向和纵向都居中；
- 数字或短标签可居中，但不要影响正文阅读。

### 3. 合并单元格

大段文字必须使用：

- 横向合并：增加阅读宽度；
- 纵向合并：提供稳定高度；
- 分块拆行：避免一个单元格装太多内容。

不要只靠单行行高解决遮挡。复制到另一个表格后，行高和列宽可能恢复默认，文字会重新被遮挡。

### 4. 复制友好

表格要考虑复制到新表后的可读性：

- 不要让关键内容依赖极端列宽；
- 不要让一个单元格承载过长正文；
- 重要段落可以拆成多块纵向合并区域；
- 长内容优先分模块，不要硬塞；
- 必要时拆成多个 sheet。

### 5. 分区

表格需要有清晰分区感：

- 项目总览；
- 背景和目标；
- 动作拆解；
- 疑问澄清；
- 深度复盘；
- 面试表达；
- 待确认内容。

但分区不能变成装饰，必须服务阅读。

## 七、语气规则

笔记语气要像产品经理复盘，不像学生作业。

少写：

- “这个项目让我学到了……”
- “体现了产品思维……”
- “这个功能很重要……”

多写：

- “这个动作对应的问题是……”
- “选择这个指标的原因是……”
- “当前方案的取舍在于……”
- “如果面试官追问，可以这样解释……”
- “这部分目前只能算合理推断，仍需补充……”

## 八、引用边界

所有结论必须能落入三类之一：

1. 资料依据；
2. 基于资料和对话的合理推断；
3. 待{称呼}补充 / 待确认。

不能把第三类写成第一类。

不能为了让项目显得更完整而编造数据、职责、结果或业务背景。
